# Markdown 编辑器产品范围与原则

> 标签：#markdown编辑器 #产品设计 #mvp #本地优先
> 日期：2026-08-06

## 目标用户

第一目标用户是使用 Windows 写技术文档的个人用户，包括开发者、学生和内容创作者。用户已经理解文件和文件夹，希望数据完全掌握在自己手中。

第一版不服务多人团队，不假设用户登录，也不建立服务端数据库。

## 核心用户任务

1. 从资源管理器或应用内打开 Markdown 文件。
2. 不记忆大量 Markdown 语法也能完成日常排版。
3. 快速插入链接、图片、列表和代码块。
4. 随时在其他 Markdown 工具中继续编辑。
5. 意外退出或发生冲突时找回内容。

## 产品原则

### 数据安全高于自动化

宁可提示用户选择，也不能静默覆盖外部修改；宁可暂缓自动保存，也不能把格式化后的内容错误写回原文件。

### 语义可靠高于逐字符无损

第一版保证声明支持的 Markdown 语义不变，允许空白、强调符号和列表编号被规范化。不能支持的语法必须明确告知，不能假装支持后再丢失。

### 编辑体验高于功能数量

中文输入法、光标、回车、删除、列表缩进、粘贴和撤销属于核心功能。命令面板、主题市场、Git 和 AI 都不是核心功能。

### 本地文件是用户资产

应用配置、缓存和恢复草稿可以使用应用数据目录；用户正文必须继续是普通 `.md` 文件，不能被私有数据库锁定。

### 先 Windows 后跨平台

Electron 天然支持跨平台，不代表第一版需要同时验证三个平台。第一版把 Windows 的路径、文件占用、安装、打印和输入法做好，再扩展 macOS 和 Linux。

## Markdown 支持分级

| 等级 | 内容 | 第一版策略 |
| --- | --- | --- |
| L0 | 段落、标题、强调、链接、列表、引用、代码 | 必须支持 |
| L1 | GFM 删除线、任务列表、自动链接 | 阶段 2 |
| L2 | 表格、脚注、Frontmatter | 阶段 3 逐项加入 |
| L3 | 数学、Mermaid、Callout | 阶段 3 或稳定版后按价值逐项加入 |
| L4 | 任意 HTML、私有扩展、插件语法 | 默认不承诺 |

详细语法契约见 [[Markdown兼容策略]]。

## MVP 范围

### In Scope

- 单窗口、单文档编辑；
- 本地打开、另存为、保存；
- L0 Markdown；
- 基础图片和链接；
- dirty 状态、退出确认和恢复草稿；
- 外部修改检测和显式冲突处理；
- 查找、撤销重做；
- Windows 安装和升级验证。

### Out of Scope

- 云服务和账号；
- 多人协作；
- 移动端；
- 插件运行时；
- 全库全文搜索；
- Git 操作；
- DOCX/EPUB；
- AI 助手；
- 完整 Typora 主题兼容。

## 非功能需求

- 用户输入到界面反馈的 P95 小于 50 ms；
- 普通文档保存后必须进行回读或哈希确认；
- 所有可能覆盖数据的操作都有显式冲突策略；
- 默认恢复点目标 RPO 为 5 秒，强杀后恢复到最近一次成功草稿检查点，不承诺最后一个按键零丢失；
- 无障碍基础操作可通过键盘完成；
- UI 进程不能直接获得任意文件系统和命令执行权限；
- 日志不记录正文、剪贴板内容和本地完整路径，除非用户主动导出诊断包。

## 不采用 Java 后端的原因

这是本地桌面应用，核心能力集中在浏览器编辑器、DOM、文件系统和桌面集成。增加 Spring Boot 或内嵌 JVM 会带来安装体积、进程管理、通信和升级复杂度，却不能解决编辑器的主要难点。

Java 可以在未来用于真正需要服务端的同步、账号或团队协作，但不进入本地 MVP。

## 验收用用户故事

```text
作为技术写作者，
我打开一个已有 Markdown 文件，
编辑标题、列表、代码和链接，
保存后可以在 VS Code 中看到语义一致的 Markdown，
应用意外关闭后能恢复到最近一次成功写入的草稿检查点。
```
