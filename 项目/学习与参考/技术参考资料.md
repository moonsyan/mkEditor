# Markdown 编辑器技术参考资料

> 标签：#markdown编辑器 #技术资料 #electron #prosemirror
> 日期：2026-08-06

## 阅读原则

优先阅读官方文档和标准，博客只用于补充案例。依赖版本以建项时官方稳定版为准，任何复制的示例都要结合当前版本 API 验证。

## 第一优先级

### Electron

- [Electron 官方文档](https://www.electronjs.org/docs/latest/)
- [Electron 安全教程](https://www.electronjs.org/docs/latest/tutorial/security)
- [Context Isolation](https://www.electronjs.org/docs/latest/tutorial/context-isolation)
- [IPC 教程](https://www.electronjs.org/docs/latest/tutorial/ipc)
- [进程模型](https://www.electronjs.org/docs/latest/tutorial/process-model)

先读进程模型、安全、context isolation 和 IPC，再写文件接口。对应 [[Electron安全架构]]。

### ProseMirror

- [ProseMirror Guide](https://prosemirror.net/docs/guide/)
- [ProseMirror Reference](https://prosemirror.net/docs/ref/)
- [ProseMirror Examples](https://prosemirror.net/examples/)

Guide 至少完整阅读 schema、document、transaction、selection、plugin 和 NodeView 相关章节。不要只通过 Milkdown API 猜底层行为。

### Milkdown

- [Milkdown 官方站点](https://milkdown.dev/)
- [Milkdown GitHub](https://github.com/Milkdown/milkdown)

重点确认当前稳定版的 preset、plugin、listener、serializer、NodeView 和 React 集成方式。阶段 0 后再决定是否正式采用。

### Markdown 标准

- [CommonMark Spec](https://spec.commonmark.org/)
- [GitHub Flavored Markdown Spec](https://github.github.com/gfm/)
- [CommonMark Discussion](https://talk.commonmark.org/)

遇到边界行为先查标准示例，不以某个编辑器的偶然表现作为标准。

## 第二优先级

### TypeScript 与 React

- [TypeScript Handbook](https://www.typescriptlang.org/docs/handbook/intro.html)
- [React Learn](https://react.dev/learn)
- [React Reference](https://react.dev/reference/react)

重点是 strict、类型收窄、Promise、ref、effect cleanup 和外部系统集成。

### Markdown 处理

- [unified](https://unifiedjs.com/)
- [remark](https://github.com/remarkjs/remark)
- [mdast](https://github.com/syntax-tree/mdast)

理解 parser、transformer、compiler 的职责，以及 mdast 只是转换过程模型。项目应用层不据此自建 remark 与 ProseMirror 转换桥；这些资料主要用于理解 Milkdown 内部机制、编写受控插件和排查往返缺陷。

### 源码编辑

- [CodeMirror System Guide](https://codemirror.net/docs/guide/)
- [CodeMirror Reference](https://codemirror.net/docs/ref/)

阶段 3 正式引入 CodeMirror 6 完整源码模式前，阅读 state、transaction、extension 和 view 生命周期。阶段 1 的安全源码兜底不依赖 CodeMirror。

## 工程与测试

- [Vite Guide](https://vite.dev/guide/)
- [electron-vite Guide](https://electron-vite.org/guide/)
- [pnpm](https://pnpm.io/)
- [Vitest Guide](https://vitest.dev/guide/)
- [Playwright Electron API](https://playwright.dev/docs/api/class-electron)
- [Playwright Best Practices](https://playwright.dev/docs/best-practices)
- [Zustand Documentation](https://zustand.docs.pmnd.rs/)

Playwright 的 Electron 支持可能带实验性限制，建项时确认当前版本状态。先自动化“打开 -> 编辑 -> 保存 -> 强杀 -> 恢复”主链路；无法稳定自动化的系统行为使用可重复脚本和 Windows 人工检查单留证，不把不存在的自动化能力设为日常开发阻断项。

## 安全资料

- [OWASP XSS Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Cross_Site_Scripting_Prevention_Cheat_Sheet.html)
- [OWASP DOM based XSS Prevention](https://cheatsheetseries.owasp.org/cheatsheets/DOM_based_XSS_Prevention_Cheat_Sheet.html)
- [DOMPurify](https://github.com/cure53/DOMPurify)
- [Electron Security](https://www.electronjs.org/docs/latest/tutorial/security)

使用 sanitizer 仍需配置 allowlist、URL 协议和 CSP，不能只调用一次函数就认为安全。

## 后续扩展

- [KaTeX](https://katex.org/docs/api.html)
- [Mermaid](https://mermaid.js.org/intro/)
- [Shiki](https://shiki.style/)
- [Tiptap](https://tiptap.dev/docs)

这些资料在对应阶段再读。Tiptap 是备选和 ProseMirror 上层设计参考，不是当前默认方案。

## 建议阅读顺序

1. TypeScript Handbook 基础与 React Learn；
2. Electron process model、security、context isolation、IPC；
3. ProseMirror Guide；
4. CommonMark 与 GFM 关键章节；
5. Milkdown 官方示例和源码结构；
6. Vitest 和 Playwright；
7. CodeMirror、KaTeX、Mermaid 按路线图后置。
