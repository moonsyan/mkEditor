# Markdown 编辑器开发路线图

> 标签：#markdown编辑器 #项目管理 #mvp #路线图
> 日期：2026-08-06

## 估算前提

以下时间使用“有效开发周”，每周约 20 小时专注投入，不等同于自然周。若每周只能投入 8～12 小时，1 个有效开发周通常对应 2～3 个自然周。时间是范围，不是承诺；每阶段只有满足退出条件才能进入下一阶段。

探索阶段的区间只覆盖当前路线正常波动，不覆盖推翻选型后的返工。阶段 0 另预留 2～4 个有效开发周作为 Milkdown 失败、缩减体验目标或改做直接 ProseMirror 小实验的缓冲；阶段 1 另预留约 30% 的文件系统、打包和恢复故障缓冲。每两周按证据重估剩余工作，不用最初日期倒逼跳过退出条件。

## 阶段 -1：学习与脚手架

建议时间：1～2 周。

交付：

- 完成 [[前端学习路线]] 的 TypeScript、React、Electron 基础部分；
- 建立 electron-vite + React + TypeScript 项目；
- 打通 main、preload、renderer 的类型化 ping 示例；
- 配置 ESLint、Prettier、Vitest、Playwright；
- 建立 CI，提交 lockfile；
- 写第一份 ADR。

退出条件：能解释 Electron 三个上下文的权限区别，renderer 中不能直接使用 `fs`。

## 阶段 0：编辑器技术验证

建议时间：4～8 周。代码允许被丢弃。

### Spike A：基础编辑

- Milkdown 初始化和销毁；
- 标题、段落、强调、列表、引用、代码块；
- 中文 IME、撤销重做、复制粘贴；
- 编辑器命令和键盘快捷键。

### Spike B：Markdown 往返

- 建立 50 个 fixture；
- 语义等价和格式幂等测试；
- 不支持语法识别；
- CRLF、BOM、中文、emoji 和代码 fence。

### Spike C：关键体验

- 当前块或 mark 标记显隐原型；
- 图片 NodeView 原型；
- 100 KB、500 KB、1 MB 性能测试；
- 使用原生文本控件完成源码模式切换原型，不做双向实时同步；可试验 CodeMirror，但不形成产品依赖。

退出条件：

- Profile Core fixture 全部通过；
- 中文输入和核心交互无发布阻断问题；
- Milkdown 通过 [[技术选型与决策]] 中 ADR-003 的门槛；
- 明确接受的格式规范化清单；
- 明确局部标记显隐做、降级或后置。

若失败：先缩小体验目标，再评估直接 ProseMirror。禁止一边失败一边继续堆文件树和导出功能。

## 阶段 1：单文档安全 MVP

建议时间：6～10 周。

交付：

- 打开、保存、另存为；
- L0 Markdown 编辑；
- dirty、保存中、保存失败和退出确认；
- FileVersion 与外部冲突；
- 恢复草稿；
- 查找、撤销重做；
- 基础图片引用；
- 解析失败或高风险语法文件的最小安全源码兜底；
- 浅色、深色基础外观；
- Windows 开发安装包。

退出条件：

- 草稿检查点成功后强杀应用，可以恢复到该检查点；普通文档默认 RPO 不超过 5 秒；
- 已检测到的外部修改不会被静默覆盖，替换关键窗口保留可恢复的前一版本；
- 保存期间连续输入不会并行写盘、错误清 dirty 或删除较新草稿；
- 保存故障注入测试通过；
- Electron 安全清单通过；
- 安装、升级和卸载不影响用户文档。

此时版本建议为 `0.1.0-alpha`，只供自己和少量技术用户试用。

## 阶段 2：桌面写作 MVP

建议时间：8～12 周。

交付：

- 用户授权的工作区和文件树；
- L1 Markdown：删除线、任务列表和自动链接；
- 新建、重命名、移动到回收站；
- 多标签页和最近文件；
- 图片粘贴与附件目录；
- 大纲、字数、查找替换；
- 自动保存；
- HTML/PDF 导出；
- 设置和快捷键基础配置；
- 文件监听与冲突 UI。

退出条件：连续 2 周日常使用无数据丢失，无 P0/P1 缺陷，性能预算和 E2E 发布门禁稳定。

此时可以发布 `0.5.0-beta`。

## 阶段 3：接近 Typora 的体验

建议时间：8～16 周，按价值逐项选择。

- CodeMirror 6 完整源码模式；
- 只读预览分屏；
- 表格可视化编辑；
- 脚注；
- 代码语言和延迟高亮；
- Frontmatter；
- KaTeX 数学公式；
- Mermaid 安全渲染；
- 更完善的局部 Markdown 标记显隐；
- 大文档降级策略。

每项功能独立使用 [[功能设计模板]]，不能打包成一个“大编辑器增强”任务。

## 阶段 4：稳定版

- 崩溃率、数据安全和性能达到发布目标；
- 自动更新与签名；
- 安装包回归；
- 隐私说明、许可和第三方依赖清单；
- 用户文档和兼容性说明；
- 至少一次从旧版本升级演练。

插件、同步、Git 和 AI 在稳定版之后独立立项。

## 每周工作方式

1. 每周只设一个可演示目标；
2. Markdown 转换先写 fixture；跨进程主链路先写或同步补上 E2E；普通 UI 和内部重构按风险选择单元或集成测试，不机械要求 E2E 先行；
3. 只有改变技术路线、跨模块契约、持久化格式或安全边界时写 ADR，普通实现决定记录在功能设计或 issue；
4. 周末用真实 Markdown 文档完成 30～60 分钟 dogfooding；
5. 记录丢数据、光标、IME、撤销和性能问题，优先于新功能；
6. 每阶段结束删除无效抽象和未使用依赖。

## 里程碑看板

```text
Backlog -> Ready -> In Progress -> Verify -> Done
```

同时只能有一个编辑器内核任务处于 In Progress。缺陷优先级：

- P0：数据丢失、安全逃逸；
- P1：崩溃、无法保存、核心输入损坏；
- P2：功能错误、有绕行方法；
- P3：视觉和低频体验问题。

P0/P1 未清零时不增加新 Markdown 扩展。
