# Markdown 编辑器测试与质量策略

> 标签：#markdown编辑器 #测试 #playwright #质量保障
> 日期：2026-08-06

## 质量目标

测试优先保护用户内容和核心编辑行为。覆盖率数字不是目标；数据安全、Markdown 语义、光标输入和真实 Electron 流程必须有针对性证据。

测试清单是随阶段扩展的风险目录，不表示每次提交都运行全部项目。日常开发运行受影响的快速测试，里程碑运行核心主链路，候选发布再执行完整 E2E、性能、安全和人工专项。

## 测试金字塔

| 层级 | 工具 | 主要对象 |
| --- | --- | --- |
| 纯逻辑单元 | Vitest | 路径、版本、规范化、错误映射 |
| 属性与 fixture | Vitest | parse/serialize、幂等性、随机文档 |
| 编辑器集成 | Vitest + jsdom 或浏览器 | command、transaction、schema |
| 浏览器交互 | Playwright | selection、粘贴、快捷键、NodeView |
| Electron E2E | Playwright Electron | 打开、保存、冲突、恢复、打印 |
| 人工专项 | Windows 实机 | 中文 IME、安装升级、系统菜单 |

jsdom 不能可信覆盖 layout、selection、composition 和 clipboard，因此关键编辑行为最终必须在真实 Chromium 验证；它们可以在相应节点或交互进入当前阶段时逐步补齐，不要求脚手架阶段一次建完整矩阵。

## Markdown 契约测试

对每个 fixture 验证：

```ts
const first = parse(input);
const output = serialize(first);
const second = parse(output);

expect(normalize(second)).toEqual(normalize(first));
expect(format(output)).toBe(output);
```

另外做属性测试：从受支持 schema 生成随机合法 ProseMirror Document，序列化后再解析，验证规范化文档等价。随机失败用 seed 固化成 regression fixture。

## 编辑器交互矩阵

每个进入当前兼容 Profile 的节点，按实现风险逐步覆盖：

- 空节点与非空节点；
- 节点开头、中间、结尾的 Backspace/Delete/Enter；
- 从上一块和下一块跨界；
- 文本选区和节点选区；
- 撤销和重做；
- 纯文本、HTML、Markdown 粘贴；
- 中文和 emoji；
- 只读状态；
- 模式切换前后。

列表额外覆盖缩进、反缩进、空项退出、嵌套粘贴和多项选择。代码块额外覆盖 fence、Tab、换行和 language。

## 文件系统测试

使用每个测试独立的临时目录，不访问真实用户笔记。覆盖：

- UTF-8、BOM、LF、CRLF、末尾换行；
- 只读、文件占用、目标不存在；
- 外部修改、删除、重命名；
- 临时写入和替换失败；
- 保存期间继续编辑；
- 同一会话并发保存被合并、相同 requestId 幂等去重、同 ID 不同 payload 被拒绝；
- 初次检查后、最终替换前外部修改；
- 用户确认覆盖后再次外部修改，必须二次冲突而不是强制写入；
- 写入后回读不一致并返回 `SAVE_OUTCOME_UNKNOWN`；
- 自身 watcher 事件抑制；
- 恢复草稿原子生成、校验、恢复和按 savedRevision 清理；
- serializer 失败时用 ProseMirror JSON 恢复，schema 不兼容时使用 Markdown fallback 或保留原草稿；
- 附件路径越界和非法文件名。

测试结束清理临时目录，但失败时允许保留路径用于诊断。

## E2E 核心场景

1. 打开 fixture，编辑并保存，外部回读验证；
2. 新文件另存为，重启后再次打开；
3. dirty 时关闭，取消、丢弃、保存三条分支；
4. 编辑后等待草稿检查点，分别强杀 renderer 和整个应用进程，重启后恢复到已确认检查点；另测检查点前立即强杀，界面不得虚假承诺最后输入已持久化；
5. 外部修改后保存，必须进入冲突而非覆盖；
6. 粘贴图片，附件与 Markdown 引用同时正确；
7. 快捷键、菜单和按钮调用同一命令结果；
8. 生产构建中 renderer 无 Node 权限；
9. 恶意 HTML、链接和路径不能越过安全边界；
10. 安装包升级后设置和正文仍存在。

阶段 1 的最低自动化主链路是第 1、4、5 项，即“打开 -> 编辑 -> 保存”“强杀 -> 恢复”和“外部修改 -> 冲突”。其余场景在对应功能进入路线图时加入，不提前为尚未实现的能力建立阻断门禁。

## 人工 IME 回归

候选发布前执行完整清单；编辑器、React 或 Electron 大版本升级合并前至少执行微软拼音连续输入、撤销重做和列表输入的最小冒烟：

- 微软拼音连续输入、候选翻页和回车上屏；
- 中英文混输；
- 标题、列表、链接、粗体和代码块中输入；
- composition 中点击其他位置；
- composition 后撤销重做；
- 长按 Backspace；
- emoji 面板和剪贴板粘贴。

结果记录到发布检查单，不以“我的机器没问题”替代用例。

## 安全测试

- IPC 发送错误类型、超大 payload、未知 channel；
- 从子 frame、非受信窗口或错误窗口复用 `fileId` 调用 IPC；
- 猜测、过期或跨窗口复用 `fileId`/`workspaceId`；
- 路径 `..`、大小写变化、符号链接/junction；
- `javascript:`、`file:` 和畸形 URL；
- 带事件属性、script、iframe 的 HTML；
- 远程图片和重定向；
- renderer 尝试访问 `process`, `require`, `ipcRenderer`；
- 导出窗口不能调用 preload API。

## 分级门禁

### 日常提交

- 受影响的 typecheck、lint、单元测试和 Markdown fixture 通过；
- 数据安全或兼容性缺陷必须先固化回归用例；
- 不要求人工安装、完整 IME 或全部 Electron E2E。

### 阶段里程碑

- 完整 unit/fixture、核心 Electron 主链路和构建通过；
- 当前阶段退出条件有测试、脚本或已记录的人工证据；
- P0/P1 为 0。

### 候选发布

- 所有单元、fixture、E2E 通过；
- P0/P1 为 0；
- 无新增未解释的兼容性差异；
- 性能关键指标相对基线退化不超过 15%，或有批准说明；
- Windows 人工 IME、安装、升级、卸载检查通过；
- Electron 安全清单通过；
- 恢复与冲突场景通过；
- 普通文档恢复检查点满足默认 5 秒 RPO，或发布说明明确例外；
- 生成第三方许可清单和构建产物哈希。

若当前 Playwright Electron 版本无法稳定自动化某一系统行为，该项可由可重复脚本加 Windows 人工检查单替代，并记录版本、步骤和结果。替代证据只适用于明确列出的场景，不能笼统声称 E2E 已覆盖。

## 缺陷最小材料

编辑器缺陷必须尽量包含：输入 Markdown、操作序列、期望结果、实际结果、系统和应用版本、是否 IME、可复现最小 fixture。使用 [[测试用例模板]] 固化回归。
