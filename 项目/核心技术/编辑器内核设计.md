# Markdown 编辑器内核设计

> 标签：#markdown编辑器 #prosemirror #milkdown #编辑器内核
> 日期：2026-08-06

## 设计目标

编辑器内核负责结构化编辑，不负责窗口、文件选择和磁盘写入。第一版使用 Milkdown 降低搭建成本，但所有设计都以 ProseMirror 的 Document、Transaction、Selection、Plugin 和 NodeView 为基础。Markdown 的 parse/serialize 由本模块内的 Milkdown 适配层统一提供；应用其他模块不直接依赖 remark AST 或自行实现转换桥。

## 核心对象

```text
EditorView
  |-- EditorState
      |-- doc: ProseMirror Document
      |-- selection
      |-- storedMarks
      |-- plugin states
  |-- dispatch(transaction)
```

- `doc`：实时编辑模式下唯一正文模型；
- `transaction`：每次结构变化、选区变化和元数据变化；
- `selection`：文本或节点选区；
- `plugin state`：大纲、当前块、装饰等编辑器局部状态；
- `NodeView`：只用于复杂节点或特殊交互，不要替换所有普通节点。

## 第一版 Schema

### Node

```text
doc
paragraph
heading(level: 1..6)
text
blockquote
bullet_list
ordered_list(order)
list_item
code_block(language?)
horizontal_rule
hard_break
image(src, alt?, title?)
```

### Mark

```text
strong
em
code
link(href, title?)
```

阶段 2 加入 `strike`、任务列表和自动链接行为；阶段 3 再逐项加入表格、脚注、Frontmatter、数学和 Mermaid。一次加入过多节点会同时放大 parser、serializer、粘贴、删除、光标和测试成本。

## 命令设计

UI 菜单、快捷键和命令面板最终都调用同一编辑命令：

```ts
type EditorCommand = {
  id: string;
  label: string;
  isEnabled(ctx: CommandContext): boolean;
  run(ctx: CommandContext): boolean;
};
```

命令返回是否执行，不直接弹窗、不写文件。需要用户输入的命令由 Application 层先收集参数，再调用编辑命令。

## 变化通知

只有 `transaction.docChanged === true` 才增加文档 revision 和 dirty。selection 变化、焦点变化和 decoration 更新不能触发自动保存。

```ts
function onTransaction(tr: Transaction): void {
  view.updateState(view.state.apply(tr));
  if (tr.docChanged) {
    documentSession.markChanged();
  }
}
```

不要把每次 transaction 放进 Zustand。大纲等投影使用节流后的插件状态或显式回调。

## Markdown 标记显隐

Typora 式体验不是简单 NodeView 切换。普通段落中的 `**`、`_`、反引号和链接语法通常已经在 parse 时变成 mark，原字符不再存在于文档树中。

建议分三步：

1. **阶段 A**：纯所见即所得，使用快捷键和浮动菜单；
2. **阶段 B**：当前块用 Decoration 显示必要提示，不允许直接编辑全部分隔符；
3. **阶段 C**：只有经过 PoC 证明后，才实现局部源码编辑或 mark 分隔符显隐。

阶段 C 必须验证：

- 光标在分隔符前后的左右移动；
- 双击、拖选和跨块选择；
- 输入法 composition 期间不切换 DOM；
- 撤销时源码和渲染状态一起恢复；
- 粘贴 Markdown 与富文本的优先级；
- 辅助功能不会因 Decoration 产生重复朗读。

## 源码模式

源码模式契约从阶段 1 开始存在，但实现分级：

- 阶段 0：只做可丢弃的模式切换 PoC，可用原生文本控件；即使试用 CodeMirror，也不形成产品依赖；
- 阶段 1：提供最小安全源码兜底，用于 parse 失败和高风险语法文件，不承诺语法高亮、完整快捷键和分屏；
- 阶段 3：正式引入 CodeMirror 6，建设完整源码模式和只读预览分屏。

无论使用哪种实现，源码与实时编辑器都不能同时接受输入。阶段归属以 [[开发路线图]] 为准。

### 进入源码模式

1. 暂停实时编辑输入；
2. 记录块级光标锚点；
3. serialize ProseMirror Document；
4. 成功后销毁或冻结 EditorView；
5. 创建当前阶段的源码控件，Markdown 字符串成为权威状态。

### 返回实时模式

1. 读取源码控件中的 Markdown 字符串；
2. parse 并收集诊断；
3. 解析失败则留在源码模式并定位错误；
4. 成功后创建 ProseMirror Document；
5. 恢复到邻近块并转移权威状态。

第一版不支持同时显示且双向实时同步的分屏编辑。预览分屏可以由源码单向、节流地生成 HTML，不能反向编辑。

源码控件发生实际文本变化时必须像 `transaction.docChanged` 一样增加 `DocumentSession.revision` 并标记 dirty；单纯进入或退出模式不增加 revision。

## NodeView 使用原则

适合 NodeView：

- 数学公式源码与渲染切换；
- Mermaid 编辑与预览；
- 图片选择、替换和错误状态；
- Frontmatter 表单或源码切换；
- 需要独立交互的代码块工具条。

不适合 NodeView：普通段落、标题、强调和简单列表。NodeView 过多会破坏 selection、复制粘贴和性能。

NodeView 内嵌 CodeMirror 时必须明确：焦点进入和退出、Escape 行为、键盘导航、撤销边界、内容提交时机、销毁清理和只读状态。

## 中文输入法

IME composition 是发布阻断项。规则：

- composition 期间不重建 EditorView 或当前 DOM；
- 不根据未完成拼音触发 Markdown input rule；
- 不在 composition 中切换 NodeView 编辑态；
- React key 不因内容变化而改变；
- 相关 E2E 必须在 Windows 真实 Electron 中手工补充验证。

自动化工具对系统输入法覆盖有限。编辑器、React 或 Electron 大版本升级合并前执行最小人工 IME 冒烟，候选发布前执行完整回归清单；普通补丁升级根据变更说明和影响范围决定。

## 粘贴策略

优先级必须固定：

1. 剪贴板包含图片文件：交给 Asset Service；
2. 明确的 Markdown 文本粘贴命令：按 Markdown 解析；
3. 普通网页富文本：清洗 HTML 后映射到 schema；
4. 纯文本：按文本插入，不擅自执行 HTML；
5. 无法映射的内容：保留可见文本并提示，而不是静默丢弃。

## 撤销边界

ProseMirror history 管理实时模式正文编辑。文件重载、模式切换、外部冲突合并和图片文件写入不是普通编辑 transaction，必须另行定义：

- 进入源码模式时冻结实时模式 `EditorState` 和 Markdown 基线；
- 未修改源码就返回实时模式时，恢复冻结的 `EditorState`，保留原撤销历史；
- 源码发生修改后返回实时模式时，以解析结果创建新的会话基线并清空 ProseMirror history；进入源码模式前的撤销链不能跨任意文本重解析继续使用；
- 源码控件自己的撤销历史只在该次源码会话内有效，退出后不与 ProseMirror history 合并；
- UI 在用户首次编辑源码前或切回时明确提示撤销历史边界；
- 外部重载创建新的会话基线；
- 图片写入失败时不提交引用，或提交带失败状态的可撤销节点；
- 保存不进入编辑历史。

## 可测试接口

```ts
interface MarkdownEditor {
  load(markdown: string): Result<void, ParseDiagnostic[]>;
  getMarkdown(): Result<string, SerializeError>;
  execute(commandId: string, args?: unknown): boolean;
  getRevision(): number;
  focus(anchor?: CursorAnchor): void;
  destroy(): void;
}
```

不要暴露整个 EditorView 给应用其他模块。确实需要的高级扩展留在 editor 模块内部注册。
