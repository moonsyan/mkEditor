# Markdown 编辑器性能与可观测性

> 标签：#markdown编辑器 #性能 #可观测性 #electron
> 日期：2026-08-06

## 性能原则

先定义用户可感知预算，再用 profile 找瓶颈。不要因为 Electron 内存高就提前迁移 Tauri，也不要在没有数据时实现复杂虚拟化。

## 第一版预算

| 场景 | 指标 | 目标 |
| --- | --- | --- |
| 冷启动到可编辑 | P50 / P95 | 小于 2 秒 / 4 秒 |
| 普通输入反馈 | Event Timing P95 | 小于 50 ms |
| 打开 100 KB 文档 | P95 | 小于 500 ms |
| 打开 1 MB 文档 | P95 | 小于 2 秒或进入降级模式 |
| 手动保存 1 MB | P95 | serialize 与文件 I/O 分别测量，总体小于 1 秒且不长时间阻塞输入 |
| 空闲 CPU | 持续采样 | 接近 0，不周期性唤醒 |
| 单文档常驻内存 | 工作集参考值 | 通过基线持续观察，不用 500 MB 当目标 |

数字需要在固定测试机器上校准。发布门禁关注相对回归和用户体验，不追求脱离环境的绝对值。

## 文档分级

```text
普通：<= 200 KB
大型：200 KB - 1 MB
超大：> 1 MB 或节点数超过阈值
```

阈值最终根据节点数、代码块和图表数量共同判断。超大文档可以：

- 禁用实时 Mermaid 和数学重渲染；
- 降低 decoration 数量；
- 延迟语法高亮；
- 阶段 1 建议进入安全源码兜底，阶段 3 后可切换完整源码模式；
- 关闭非必要大纲实时更新；
- 显示明确提示而不是无响应。

## 高频路径规则

- ProseMirror transaction 直接更新 EditorView；
- docChanged 才更新 revision；
- 大纲、字数和状态栏使用节流投影；
- React 不根据每次 selection 重渲染整个页面；
- NodeView `update` 先比较 attrs 和内容，避免无条件重建；
- 代码高亮、Markdown 预览和搜索可移入 Worker；
- Mermaid、KaTeX 和图片采用可见时渲染或延迟渲染。

## 测量点

使用 `performance.mark/measure` 记录：

```text
app.start -> editor.ready
file.read.start -> file.read.end
markdown.parse.start -> markdown.parse.end
editor.mount.start -> editor.mount.end
markdown.serialize.start -> markdown.serialize.end
file.save.start -> file.save.end
recovery.serialize.start -> recovery.write.end
```

每条记录带文档大小桶、节点数桶和功能开关，不带正文、文件名或完整路径。

## 日志

日志等级：

- `error`：保存失败、恢复失败、未处理异常；
- `warn`：解析降级、冲突、性能预算超限；
- `info`：应用启动、版本、打开/保存结果和更新状态；
- `debug`：开发环境诊断，生产默认关闭。

日志使用结构化字段和 diagnostic ID。严禁记录：正文、剪贴板、访问令牌、完整本地路径、HTML 原始输入。

## 崩溃与诊断

第一阶段允许完全本地诊断，不必接入云遥测：

- renderer 和 main 未处理异常写本地日志；
- 崩溃后保留恢复草稿；
- 设置页提供“导出诊断包”；
- 导出前列出内容并默认脱敏路径；
- 用户明确同意后才分享。

## 基准文档

建立固定 fixture：

- 100 KB 普通中文长文；
- 1 MB 混合 Markdown；
- 1000 个列表项；
- 200 个代码块；
- 100 张本地图片引用；
- 大型单行文本；
- 深层嵌套列表；
- 后期加入 50 个 Mermaid 和数学块。

基准文件进入仓库，但避免包含真实用户内容。

## 性能回归流程

1. 固定 Electron、Node、测试机配置、电源模式和后台进程条件；
2. 日常探索可跑 5 次，只比较中位数、范围和明显异常，不从 5 个样本声称 P95；
3. 候选发布至少采集 30 个有效样本，冷启动与热启动分开统计，再比较中位数、P95 和内存峰值；
4. 相对基线退化超过 15% 时在相同条件下复跑确认，避免把环境噪声当回归；
5. 用 Chromium Performance、Memory、Electron trace 或 Node profile 定位；
6. 修复后保留回归用例和同条件基线。
