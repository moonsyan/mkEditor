## 模块职责

### `main/file`

- 用户授权后的文件读取；
- 原子写入、版本比较和备份；
- 文件监听和自身写入抑制；
- 编码、BOM、EOL 和权限信息处理。
- 为窗口签发和回收不透明 `fileId`，维护到规范化真实路径的映射。

这里是唯一可以写用户正文的模块。要求见 [[文件与数据安全]]。

### `main/ipc`

- 注册固定 IPC channel；
- 使用 schema 校验输入；
- 将系统异常映射成稳定错误码；
- 校验请求对应的窗口和授权范围。

### `preload`

只暴露类似下面的窄接口：

```ts
type DesktopAPI = {
  document: {
    open(): Promise<Result<FileSnapshot, DesktopError>>;
    save(request: SaveRequest): Promise<Result<SaveResult, DesktopError>>;
    saveAs(request: SaveAsRequest): Promise<Result<SaveResult, DesktopError>>;
  };
  external: {
    openUrl(url: string): Promise<Result<void, DesktopError>>;
  };
};
```

`SaveRequest` 使用 Main 签发的 `fileId`，不接受 renderer 自行构造的绝对路径。禁止暴露通用 `invoke(channel, payload)`。

### `features/editor`

- 创建和销毁 Milkdown/ProseMirror 实例；
- 注册 schema、mark、command、keymap 和 NodeView；
- 用单一 adapter 暴露 Milkdown parse/serialize，不在应用层另建 remark 与 ProseMirror 转换桥；
- 向 DocumentSession 提交“内容已变化”信号；
- 提供序列化、解析诊断和光标锚点能力。

不负责文件路径、对话框或写磁盘。

### `features/document`

- 管理 `DocumentSession`；
- 打开、保存、另存为、关闭；
- dirty、saving、conflicted、recovery 状态机；
- 协调 EditorPort 与 FilePort；
- 保证每个会话最多一个保存请求在途，将后续变化合并到最新 revision；
- 处理旧 revision 保存成功后的基线更新、dirty 保留和恢复草稿清理边界。

这里是上述会话状态的唯一写入入口。Zustand slice 若需要展示这些字段，只能订阅 `DocumentSession` 快照，不能拥有独立 action 修改它们。

### `features/workspace`

第二阶段再启用。负责授权目录、文件树投影、重命名和外部变化，不负责正文编辑。

### `core/markdown`

- 定义支持的 Markdown profile；
- 定义 `MarkdownCodec` 契约、规范化规则和诊断类型；
- 规范化和诊断；
- fixture 共享工具。

具体 parser/serializer 映射由 `features/editor` 中的 Milkdown adapter 实现。`core/markdown` 不直接维护一条独立 unified/remark pipeline。

## Port 边界

```ts
interface FilePort {
  open(): Promise<Result<FileSnapshot, FileError>>;
  save(request: SaveRequest): Promise<Result<SaveResult, FileError>>;
  watch(fileId: string): Promise<Result<WatchHandle, FileError>>;
}

interface EditorPort {
  load(markdown: string): Result<void, ParseError>;
  serialize(): Result<string, SerializeError>;
  focus(anchor?: CursorAnchor): void;
}
```

Port 是业务边界，不是为了形式上的“六边形架构”。若接口只有一个调用者且没有隔离价值，可以保持为普通模块函数。

## 错误模型

不要把 Node 异常消息直接显示给用户。定义稳定错误类型：

```ts
type FileError =
  | { code: 'NOT_FOUND'; pathLabel: string }
  | { code: 'PERMISSION_DENIED'; pathLabel: string }
  | { code: 'CONFLICT'; actual: FileVersion }
  | { code: 'LOCKED'; pathLabel: string }
  | { code: 'SAVE_OUTCOME_UNKNOWN'; diagnosticId: string }
  | { code: 'IO_ERROR'; diagnosticId: string };
```

用户消息使用中文，诊断日志保留安全的技术原因。完整路径默认不进入遥测或普通日志。

## 何时拆分 package

满足任一条件才拆：

- 至少两个应用真实复用；
- 需要独立版本和独立测试发布；
- 模块依赖已经稳定，拆分能被工具强制；
- 构建性能数据证明拆分有收益。

首个可拆对象通常是 `editor-core`，其次是 `markdown-profile`。文件、窗口和更新仍应留在桌面应用中。
