# 排障与缺陷记录

> 更新基线：2026-08-12。本文保留会影响用户数据或后续维护决策的已确认问题，不记录失效行号和阶段性审查统计。

## 连续撤销导致内容混乱或跨文件串联

### 问题现象

多次打开工作区文件，将最后一个预览文件固定并持续编辑后，连续按 `Ctrl+Z`，内容可能回退到空白、出现从未在当前文件中编辑过的文本，甚至混入其他文件内容。

### 排查过程

1. 复现“打开多个文件 → 固定预览标签 → 编辑 → 多次撤销”，确认问题与文件切换后的撤销历史有关。
2. 检查 Milkdown `replaceAll` 实现，发现默认 `flush=false`，全文替换以普通 transaction 进入 ProseMirror history。
3. 检查 Wiki 自动转换事务，确认程序性节点替换也会进入同一 history。
4. 追踪 `markdownUpdated`，确认监听器存在约 200ms 防抖，旧文件回调可能在切换后到达。
5. 检查工作区读取链路，确认多个异步读取可能按与点击相反的顺序完成。

### 根因

问题由四个状态边界叠加产生：跨文档全文替换进入撤销栈、Wiki 自动转换污染历史、旧文档防抖回调按当前文件 ID 写入，以及较早的慢读取反向激活文件。

### 解决思路

把“用户编辑”和“程序性文档切换”从历史语义上隔离；在接收异步结果时校验结果仍属于当前操作意图，而不是只相信回调触发时的活动文件 ID。

### 最终解决

- 文档切换使用 `replaceAll(markdown, true)` 重建 `EditorState`，清空跨文件 undo/redo 历史。
- Wiki 自动转换设置 `addToHistory=false`。
- `EditorHandle` 增加 `getMarkdown()`；延迟回调与当前编辑器 Markdown 不一致时丢弃。
- 使用 `latestWorkspaceSelectionRef`，只允许最后一次文件选择激活编辑器。
- 属性面板等程序性更新统一走 `replaceEditorContent()`。

### 回归验证

在多个文件之间快速切换并编辑，连续撤销应最多回到当前文件打开时的内容；不得清空当前文件，不得出现其他文件内容。自动化测试覆盖旧回调归属判断，构建和现有测试集均通过。

## Wiki 路径、别名与保存失败

### 问题现象

已有文档中的 `[[目录/文件|别名]]` 在切换标签后不渲染为链接；保存包含 Wiki 节点的文档时可能抛出未知 Markdown AST 节点错误。

### 排查过程与根因

Wiki 文本转换插件的 `view()` 只在编辑器创建时执行，复用编辑器切换文件不会再次触发。初版序列化又输出了未被 Markdown 序列化器注册的自定义节点；尝试普通文本节点时，方括号会被转义。

### 解决思路与结果

文件切换后显式调用 `convertWikiTextInDoc()`；序列化通过受支持的 `html` AST 节点原样输出 Wiki 源文本。使用真实的路径、下划线和别名语料验证加载、点击和保存往返，代码块及 frontmatter 中的文本保持不转换。

## Frontmatter 属性编辑破坏复杂 YAML

### 问题现象

把整个 frontmatter 解析成简单对象再重新格式化，会丢失注释、嵌套数组或对象，并可能改变 CRLF 文档的换行。删除最后一个属性还可能残留围栏或空行。

### 排查过程与根因

简单键值解析器不能无损表达完整 YAML；全量序列化天然会覆盖未识别结构。原实现还隐含使用 LF 拼接，未保留原文换行类型。

### 解决思路与结果

属性面板只暴露可安全识别的简单键值，更新时定位并替换对应行，未识别的 YAML 行和注释原样保留。提取和写回均保留 LF/CRLF；删除最后一个属性时移除整个块。复杂 YAML 仍可在正文节点中直接编辑，不承诺表单化处理。

## 专注模式无法按 Escape 退出

### 问题现象

开启专注模式后，界面隐藏，但按 `Escape` 无法恢复普通模式。

### 排查过程与根因

专注模式只有 F11/菜单切换动作，没有独立的 Escape 退出监听。应用内多个弹窗和查找栏也使用 Escape，不能无条件抢占该按键。

### 解决思路与结果

专注模式开启时注册键盘监听：非输入法组合状态下按 Escape 退出；如果查找栏、设置、帮助、图片管理、PDF 选项或工作区搜索仍打开，则先保留对应组件的 Escape 处理，避免快捷键冲突。

## 新工作区文件树默认全部展开

### 问题现象

首次打开或切换到没有历史记录的工作区时，目录默认全部展开；用户明确展开全部后的状态也可能与“没有记录”混淆。

### 排查过程与根因

折叠集合使用空数组表示“没有折叠项”，但初始化同样使用空数组，无法区分“从未持久化”和“用户明确展开全部”。

### 解决思路与结果

使用 `null` 表示无历史记录，`[]` 保留为用户明确展开全部。无记录或记录与新工作区不匹配时默认全部折叠；`usePersistedSetting` 不写回 `null`，避免初始化覆盖已有设置。

## 快速连续打开文件时激活顺序错误

### 问题现象

快速点击多个文件时，最后显示的文件偶尔不是最后点击的文件，单击和双击还可能竞争创建标签。

### 排查过程与根因

文件读取异步完成，较早点击的慢请求可能最后返回；仅按返回顺序更新活动文件会覆盖用户较新的选择意图。

### 解决思路与结果

记录最后一次工作区文件选择路径，请求完成后再次校验；过期请求可以结束读取，但不能激活编辑器。同一路径合并在途请求，完成后复查已打开标签，避免重复标签。

## 长期维护边界

- Electron 启动 Promise、窗口事件和 IPC 异步链必须有明确错误处理，不能依赖未处理拒绝。
- 与 `WebContents` 关联的状态使用 `WeakMap` 等外部结构，不向 Electron 对象临时挂载私有字段。
- 第三方类型不完整时，`@ts-expect-error` 必须说明具体兼容原因；不得使用无说明的宽泛断言掩盖错误。
- 搜索、代码行号等模块级控制器依赖当前单编辑器实例。若改为多编辑器并存，必须先改为按 EditorView 隔离状态。
- 预览 `innerHTML` 当前只接收 ProseMirror 生成的可信 DOM 快照；未来若允许原始 HTML 透传，必须先增加清理和白名单。
- 自动保存、手动保存、图片上传和搜索 Worker 必须保留冲突检测、超时、体积上限、正则执行超时及失败状态清理。
