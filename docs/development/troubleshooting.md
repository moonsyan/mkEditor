# 排障与缺陷记录

> 更新基线：2026-08-15。本文保留会影响用户数据或后续维护决策的已确认问题，不记录失效行号和阶段性审查统计。

## 移动文件时活动文档内容被清空

### 问题现象

移动文件后，活动文档内容被清空，状态栏显示未保存；下次自动保存会把空内容写回磁盘，覆盖原文。

### 排查过程与根因

`handleMoveFile` 先改写 `activeFileIdRef` 再取编辑器实时内容。`liveContentOf` 的快路径要求 `id === activeFileIdRef.current`，而 `contentsRef` 此时已迁移（旧 id 键被删除），先改写 ref 会让兜底分支读到空串。

### 解决思路与结果

改写 `activeFileIdRef` 之前先从编辑器取实时内容，取到的是 flush 落账后的实时值，防抖窗口内也不滞后。

## 保存 CONFLICT 误报外部修改

### 问题现象

自动保存/手动保存遇到 CONFLICT 时提示"已被外部修改"，但实际是自冲突：上次保存成功后 mtime 未及时回填、或内容未变又被重新保存，用户被反复打扰。

### 排查过程与根因

保存返回 CONFLICT 时未区分自冲突与真实外部修改，一律按外部修改处理。

### 解决思路与结果

`App.tsx` 新增 `resolveSelfConflict`：遇到 CONFLICT 先重读磁盘，磁盘内容与本次写入一致则视为自冲突，静默视为保存成功并回填 mtime、更新已保存基线；仅当磁盘内容确实不同才提示外部修改——自动保存跳过并 Toast 提示，手动保存弹确认框。

## 预览标签丢弃丢失末次输入

### 问题现象

侧栏打开下一个预览前会丢弃前一个预览标签；若该标签是活动文档且 200ms 防抖窗口内刚有输入（编辑器实时内容未落账），直接丢弃会丢末次输入。

### 排查过程与根因

`discardPreviewTab` 只按标签状态判定可丢弃，未检查编辑器实时内容是否已落账。

### 解决思路与结果

丢弃前比对编辑器实时内容与已落账内容：不一致时先落账并自动固定为普通标签（与编辑自动 pin 机制一致），不丢弃；外层调用继续打开下一个文件，两个标签并存，内容不丢。

## 分散文件粘贴/保存图片被拒绝

### 问题现象

未加入工作区的分散 .md（拖入或会话恢复打开）中粘贴图片报 `INVALID_PATH`，图片无法插入。

### 排查过程与根因

`FILE_READ` 为分散文件授予 `trustFileForSave`，但 `FILE_SAVE_IMAGE` 只接受完整信任根 `ensureTrusted`，双重信任模型不一致。

### 解决思路与结果

与 `FILE_SAVE` 一致，改为 `ensureTrusted || isFileTrustedForSave` 双重判定，分散文件中保存图片不再被拒绝。

## trusted-roots 多进程覆写丢失信任

### 问题现象

多窗口模式下，其他窗口登记过的信任在重启后丢失。

### 排查过程与根因

多窗口模式存在多个独立主进程，各自整体覆写 `trusted-roots.json`，互相覆盖对方已登记的信任。

### 解决思路与结果

`persistTrustSnapshot` 写盘前合并磁盘上既有快照（workspaces / files / imageDirs 取并集），再截断到持久化上限（工作区 8 / 文件 256 / 图片目录 64 个，超出淘汰最早登记的），各进程互不覆盖。

## trusted-roots 清单无界增长

### 问题现象

`files` / `imageDirs` 清单长期使用后无上限累积，重启恢复变慢、文件持续膨胀。

### 排查过程与根因

持久化清单原无容量上限（仅 workspaces 有上限 8）。

### 解决思路与结果

新增 `MAX_PERSISTED_FILES=256`、`MAX_PERSISTED_IMAGE_DIRS=64`（与运行时图片读取白名单上限一致），超出淘汰最早登记的；workspaces 保持原 `MAX_PERSISTED_WORKSPACES=8`。

## mdimg 图片被 CSP 拒绝不显示

### 问题现象

文档中的本地图片完全不显示（`naturalWidth=0`），控制台报 CSP 拒绝 `mdimg:` 资源。

### 排查过程与根因

页面 CSP 为 `default-src 'self'`，`mdimg` 为自定义 scheme 与文档不同源；`registerSchemesAsPrivileged` 未声明 `bypassCSP` 时 `<img src="mdimg:///...">` 被 CSP 直接拒绝（真实 Electron 对照实验验证）。

### 解决思路与结果

`registerSchemesAsPrivileged` 为 `mdimg` 增加 `bypassCSP: true`。信任边界不变：`fetchAllowedImage` 仍做工作区根目录 + realpath 双重校验，放行 CSP 不会放开读取。

## 导出 HTML/PDF 图片全部破图

### 问题现象

导出 HTML/PDF 后本地图片全部不显示。

### 排查过程与根因

原 `inlineImagesInHtml` 用渲染层 `fetch(mdimg://)` 内联图片；Blink 对自定义 scheme 的 fetch 必然抛 `TypeError`，导出文件里的图片全部破图。

### 解决思路与结果

新增 IPC 通道 `FILE_READ_IMAGE_INLINE`（`file:read-image-inline`），preload 暴露 `document.readImageInline(src)`；主进程 `readImageAsDataUrl` 与 mdimg 协议共用 `resolveAllowedImagePath` 校验（词汇级信任根/白名单 + realpath 防符号链接逃逸），读为 base64 data URL，单图 64MB 上限防 OOM。内联失败保留原路径。

## 带 BOM 的 UTF-8 保存后 BOM 丢失

### 问题现象

带 BOM 的 UTF-8 文件保存后被字节级改写为无 BOM，依赖 BOM 判断编码的工具链会误判。

### 排查过程与根因

原实现剥掉 BOM 解码后按 `'UTF-8'` 保存，BOM 被静默丢弃。

### 解决思路与结果

读取时对带 BOM 的 UTF-8 记独立编码 `'UTF-8-BOM'`，保存时写回 BOM；状态栏显示 `UTF-8 (BOM)`。

## 无 BOM 的 UTF-16 文件乱码且保存后不可逆损坏

### 问题现象

无 BOM 的 UTF-16 文件（如 Windows 记事本「UTF-16 LE」另存）打开显示乱码，保存写回 GBK 把原文件不可逆改写。

### 排查过程与根因

原实现缺少无 BOM 的 UTF-16 探测，此类文件落入 GBK 宽松解码，保存按 GBK 写回即损坏原文件。

### 解决思路与结果

新增 `detectUtf16NoBom`：抽样前 8KB 统计零字节两侧占比，一侧 ≥30% 且另一侧 ≤5% 判定为 UTF-16LE/BE。纯中文 UTF-16 零字节占比低（仅换行符）探测不出，追加兜底：GBK 解码结果含 NUL 控制字符（UTF-16 特征，正常 GBK 文件不含）时再走 UTF-16 判定。探测成功后按 UTF-16 原编码保存。

## 多窗口模式同路径并发保存互相覆盖

### 问题现象

多窗口模式下两个窗口保存同一路径的文件时互相覆盖对方的写入。

### 排查过程与根因

多窗口模式存在多个独立主进程，进程内 `saveLocks` Map 互相不可见，同路径并发保存的冲突检测 stat 都落在对方写入之前。

### 解决思路与结果

新增 `acquireCrossProcessSaveLock`：独占创建 `<path>.mkedit-save-lock`（写入 pid + 时间戳），创建成功者持锁，竞争者轮询等待；锁 mtime 超过 10 秒且持有者进程不存活（崩溃残留）→ 删除残留锁重试竞争；总等待超过 30 秒返回错误码 `SAVE_LOCKED`（手动保存 toast 提示稍后重试，自动保存静默跳过、下轮自动重试）。锁覆盖 stat 校验 + 冲突检测 + 写盘全流程。

## 打开第 65 个目录后已打开文档图片破图

### 问题现象

连续打开大量目录后，仍在打开的文档里的 mdimg 图片读取失效（破图）。

### 排查过程与根因

`FILE_OPEN` 授予的目录信任根为非保底（64 上限，最早淘汰）；打开第 65 个目录后最早的根被淘汰，已打开文档的图片读取随之失效。

### 解决思路与结果

`FILE_OPEN` 补 `allowImageDirectory(dirname(filePath))`：图片读取白名单独立于 `trustedRoots` 且只读（不授予写/删/搜权限），即使目录信任被淘汰，文档里的图片仍可显示。

## PDF 导出临时文件写入失败无响应

### 问题现象

磁盘满或权限不足时，PDF 导出的临时 HTML 写入失败，异常直接抛出 IPC，渲染层 promise 永不 resolve，导出操作无任何反馈。

### 排查过程与根因

临时 HTML 写入位于 try 保护之外，错误路径没有结构化结果。

### 解决思路与结果

写入移入 try 保护，失败返回 `IO_ERROR` 结构化错误（"无法写入临时文件"），渲染层可正常收尾。

## 设置值 stringify 为 undefined 时崩溃

### 问题现象

设置 updater 返回 `undefined`（如删除 key）时，保存设置抛 `TypeError` 崩溃。

### 排查过程与根因

`JSON.stringify(undefined)` 返回 `undefined`，后续 `Buffer.byteLength(undefined)` 抛 `TypeError`，且该调用位于 try 之外。

### 解决思路与结果

序列化值为 `undefined` 时显式抛 `INVALID_VALUE` 结构化错误。

## 粘贴/拖入图片保存失败静默

### 问题现象

图片保存失败时静默返回，用户以为图片已插入，实际没有落盘。

### 排查过程与根因

`useImageInsertion` 未检查保存结果即 return，失败路径无用户反馈。

### 解决思路与结果

保存失败按错误码明确提示：`TOO_LARGE` 提示"图片超过 20MB，无法插入"；其他失败提示"图片保存失败，请检查文件权限或磁盘空间"。

## 导出时 mermaid 渲染失败/未完成丢失源码

### 问题现象

mermaid 语法错误或 4 秒等待超时未完成时导出，导出内容只剩错误/加载文案，图表源码从导出中丢失。

### 排查过程与根因

导出克隆 DOM 时，凡非源码编辑态的 mermaid 块一律删除源码 pre；渲染失败或超时状态下块内无 SVG、也不在源码编辑态，源码 pre 被误删。

### 解决思路与结果

块内无渲染 SVG 时保留源码 pre，以源码文本导出，内容不丢；仅在预览态且有渲染 SVG 时删除 pre。

## 折叠小节光标盲打与全选误删

### 问题现象

章节折叠仅用 `display:none` 隐藏，方向键可从标题进入隐藏区盲打；Ctrl+A 全选后输入会静默替换折叠内容。

### 排查过程与根因

ProseMirror 不知道折叠区不可见，选区可自由进出隐藏区，键盘输入落到不可见内容。

### 解决思路与结果

`sectionFold` 插件新增 `handleKeyDown` 三层守卫：① Ctrl/Cmd+A 先展开全部折叠再全选，全选语义完整；② 选区已在隐藏区内时任何按键 clamp 回标题文本末尾；③ ↓/→（含 PageDown）从折叠标题移动时跳到隐藏区后的可见位置，↑/←（含 PageUp）从隐藏区末尾向回移动时 clamp 回标题文本末尾。

## 标题级别变更后折叠范围错位

### 问题现象

标题级别变更（如 `#` 降级为 `##`，setNodeMarkup）后，折叠隐藏范围与真实折叠范围不一致，可能隐藏了不该隐藏的块。

### 排查过程与根因

折叠范围 `[nodeEnd, end)` 依赖标题级别；setNodeMarkup 事务无 slice，快速路径复用旧装饰，级别变化未触发重建。

### 解决思路与结果

检测到 setNodeMarkup 且目标是 heading 时跳过快速路径，按新 doc 重建折叠装饰。

## 程序性更新光标漂移

### 问题现象

属性面板编辑 frontmatter 后，光标落在错误行——文档开头内容长度变化时正文坐标整体偏移。

### 排查过程与根因

`updateContentPreservingHistory` 用旧文档坐标直接恢复选区，未做坐标映射。

### 解决思路与结果

改为复刻全文替换事务（保留撤销历史，Ctrl+Z 可回退），用 `tr.mapping` 精确映射旧坐标恢复光标；滚动位置仍手动恢复。

## 内容解析失败静默失败

### 问题现象

畸形输入使 parser 抛错时，编辑器停在旧文档，代码面板/表格工具栏残留旧 DOM 引用，用户无任何提示。

### 排查过程与根因

parser 同步执行 remark 管道，异常从切换/更新调用链逃逸，未走与成功一致的收尾。

### 解决思路与结果

`applyReplaceContent` 包 try/catch：失败时走与成功一致的收尾（清浮层、清状态）并提示"内容无法解析，已保留原文档"，内容不丢失。

## 代码块行号幽灵块残留

### 问题现象

删除起点恰为代码块起点（Ctrl+A 后输入、选中块起点删除）后，行号仍按陈旧块信息显示，后续触碰代码块的事务按旧 blocks 重建，出现幽灵块。

### 排查过程与根因

行号快速路径 `mapCodeBlockLines` 只依赖 `tr.mapping.mapResult` 的 `deleted` 标志；删除起点恰为块起点时 ProseMirror 不置 `deleted`，映射后的位置可能已不是 `code_block`。

### 解决思路与结果

映射后校验 `tr.doc.nodeAt(mapped.pos)` 节点类型，不是 `code_block` 即剔除该块走全量重建。

## 连续撤销导致内容混乱或跨文件串联

### 问题现象

多次打开工作区文件，将最后一个预览文件固定并持续编辑后，连续按 `Ctrl+Z`，内容可能回退到空白、出现从未在当前文件中编辑过的文本，甚至混入其他文件内容。

### 排查过程

1. 复现“打开多个文件 → 固定预览标签 → 编辑 → 多次撤销”，确认问题与文件切换后的撤销历史有关。
2. 检查 Milkdown `replaceAll` 实现，发现默认 `flush=false`，全文替换以普通 transaction 进入 ProseMirror history。
3. 检查 Wiki 自动转换事务，确认程序性节点替换也会进入同一 history。
4. 追踪 `markdownUpdated`，确认监听器存在约 200ms 防抖，旧文件回调可能在切换后到达。
5. 检查工作区读取链路，确认多个异步读取可能按与点击相反的顺序完成。

### 根因

问题由四个状态边界叠加产生：跨文档全文替换进入撤销栈、Wiki 自动转换污染历史、旧文档防抖回调按当前文件 ID 写入，以及较早的慢读取反向激活文件。

### 解决思路

把“用户编辑”和“程序性文档切换”从历史语义上隔离；在接收异步结果时校验结果仍属于当前操作意图，而不是只相信回调触发时的活动文件 ID。

### 最终解决

- 文档切换使用 `replaceAll(markdown, true)` 重建 `EditorState`，清空跨文件 undo/redo 历史。
- Wiki 自动转换设置 `addToHistory=false`。
- `EditorHandle` 增加 `getMarkdown()`；延迟回调与当前编辑器 Markdown 不一致时丢弃。
- 使用 `latestWorkspaceSelectionRef`，只允许最后一次文件选择激活编辑器。
- 属性面板等程序性更新统一走 `replaceEditorContent()`。

### 回归验证

在多个文件之间快速切换并编辑，连续撤销应最多回到当前文件打开时的内容；不得清空当前文件，不得出现其他文件内容。自动化测试覆盖旧回调归属判断，构建和现有测试集均通过。

## Wiki 路径、别名与保存失败

### 问题现象

已有文档中的 `[[目录/文件|别名]]` 在切换标签后不渲染为链接；保存包含 Wiki 节点的文档时可能抛出未知 Markdown AST 节点错误。

### 排查过程与根因

Wiki 文本转换插件的 `view()` 只在编辑器创建时执行，复用编辑器切换文件不会再次触发。初版序列化又输出了未被 Markdown 序列化器注册的自定义节点；尝试普通文本节点时，方括号会被转义。

### 解决思路与结果

文件切换后显式调用 `convertWikiTextInDoc()`；序列化通过受支持的 `html` AST 节点原样输出 Wiki 源文本。使用真实的路径、下划线和别名语料验证加载、点击和保存往返，代码块及 frontmatter 中的文本保持不转换。

## Frontmatter 属性编辑破坏复杂 YAML

### 问题现象

把整个 frontmatter 解析成简单对象再重新格式化，会丢失注释、嵌套数组或对象，并可能改变 CRLF 文档的换行。删除最后一个属性还可能残留围栏或空行。

### 排查过程与根因

简单键值解析器不能无损表达完整 YAML；全量序列化天然会覆盖未识别结构。原实现还隐含使用 LF 拼接，未保留原文换行类型。

### 解决思路与结果

属性面板只暴露可安全识别的零缩进顶层标量，更新时定位并替换对应行，未识别的 YAML 行和注释原样保留。内联数组、块级数组、对象、多行值、锚点、显式类型和带行内注释的属性不进入面板，复杂同名键也不能被新增表单覆盖。提取和写回均保留 LF/CRLF；删除最后一个简单属性且只剩空行或注释时移除整个块。复杂 YAML 仍可在正文节点中直接编辑，不承诺表单化处理。

属性面板此前在收起时连标题栏一起卸载，导致无法直接重新展开。渲染条件现只判断当前文件和内容是否存在，展开状态仅控制属性表格，标题栏始终保留。

## 专注模式无法按 Escape 退出

### 问题现象

开启专注模式后，界面隐藏，但按 `Escape` 无法恢复普通模式。

### 排查过程与根因

专注模式只有 F11/菜单切换动作，没有独立的 Escape 退出监听。应用内多个弹窗和查找栏也使用 Escape，不能无条件抢占该按键。

### 解决思路与结果

专注模式开启时注册键盘监听：非输入法组合状态下按 Escape 退出；如果查找栏、设置、帮助、图片管理、PDF 选项或工作区搜索仍打开，则先保留对应组件的 Escape 处理。监听器还会检查 `defaultPrevented`，输入框、重命名或其他子控件已经消费 Escape 时不同时退出专注模式。

## 侧栏文字过小且键盘无法操作

### 问题现象

文件树和大纲正文原本约为 11 至 12px，低级大纲标题还会继续缩小；侧栏标签、文件节点和大纲项主要依赖鼠标点击。

### 解决思路与结果

文件树和大纲正文统一调整为 14px，并同步增加行高和点击区域。标题层级改用字重与颜色表达。侧栏标签改为原生按钮，文件树节点增加 tree 语义与 Enter/空格操作，大纲项增加按钮语义和左右方向键折叠，同时补充统一的可见焦点样式。

## 新工作区文件树默认全部展开

### 问题现象

首次打开或切换到没有历史记录的工作区时，目录默认全部展开；用户明确展开全部后的状态也可能与“没有记录”混淆。

### 排查过程与根因

折叠集合使用空数组表示“没有折叠项”，但初始化同样使用空数组，无法区分“从未持久化”和“用户明确展开全部”。

### 解决思路与结果

使用 `null` 表示无历史记录，`[]` 保留为用户明确展开全部。无记录或记录与新工作区不匹配时默认全部折叠；`usePersistedSetting` 不写回 `null`，避免初始化覆盖已有设置。

## 快速连续打开文件时激活顺序错误

### 问题现象

快速点击多个文件时，最后显示的文件偶尔不是最后点击的文件，单击和双击还可能竞争创建标签。

### 排查过程与根因

文件读取异步完成，较早点击的慢请求可能最后返回；仅按返回顺序更新活动文件会覆盖用户较新的选择意图。

### 解决思路与结果

记录最后一次工作区文件选择路径，请求完成后再次校验；过期请求可以结束读取，但不能激活编辑器。同一路径合并在途请求，完成后复查已打开标签，避免重复标签。

## 长期维护边界

- Electron 启动 Promise、窗口事件和 IPC 异步链必须有明确错误处理，不能依赖未处理拒绝。
- 与 `WebContents` 关联的状态使用 `WeakMap` 等外部结构，不向 Electron 对象临时挂载私有字段。
- 第三方类型不完整时，`@ts-expect-error` 必须说明具体兼容原因；不得使用无说明的宽泛断言掩盖错误。
- 搜索、代码行号等模块级控制器依赖当前单编辑器实例。若改为多编辑器并存，必须先改为按 EditorView 隔离状态。
- 章节折叠的键盘守卫、行号与折叠装饰的节点类型校验、mermaid 导出的源码兜底、保存冲突的自冲突消解、跨进程保存锁、编码原样写回（BOM / UTF-16 / GBK）与图片信任双重校验属于数据安全边界，改动时必须保留对应的手工回归验证。
- 预览 `innerHTML` 当前只接收 ProseMirror 生成的可信 DOM 快照；未来若允许原始 HTML 透传，必须先增加清理和白名单。
- 自动保存、手动保存、图片上传和搜索 Worker 必须保留冲突检测、超时、体积上限、正则执行超时及失败状态清理。
